# Geo Icon：用几何构造画图标

你写的是**构造**，不是轮廓。一份 JSON 规格描述圆、环、切线、两弧夹出的叶形 (lune)、相切圆弧链、凸包和布尔运算。
脚本据此算出最终轮廓，并把同一批图元画回构图卡上当作构造线。所以构造线就是形状的来源，不是事后贴上去的装饰。
这正是 Rikyu 样张 before/after 的区别（详见 `references/method.md`）。

## 产物

`python3 <本 skill 目录>/scripts/geoicon.py spec.json -o <输出目录>` 生成：

| 文件 | 内容 |
|---|---|
| `icon.svg` | 最终 mark：单色、单条 evenodd 路径、方形 viewBox。轮廓沿构造圆的部分写成真正的 SVG 圆弧 `A`，直段写成 `L` |
| `poster.png/.svg` | 米白 4:5 画布上居中的成品图 |
| `construction.png/.svg` | 构图卡：方格纸、浅灰实填的形状、构造圆、切线、圆心十字、底部 CONCEPT 文案、右下角成品缩略图。默认只画最终落在轮廓上的圆和线；gap 缝画成成对的同心圆 |
| `sizes.png/.svg` | 128→16px 正反色小尺寸测试 |
| `compare.png/.svg` | 仅在规整现有图标时（`--compare 原图`）：原图、规整后、叠加三联对比 |
| `report.txt` | 体检：bbox 与重心、碎片数、半径种类、过细部位、会糊掉的窄缝 |

依赖 `shapely>=2`、`numpy`、`Pillow`（缺失时运行 `python3 -m pip install -r <本 skill 目录>/requirements.txt`）。PNG 依次尝试 rsvg-convert、cairosvg、
Chrome/Edge 无头模式、macOS qlmanage；都没有就只出 SVG。一次渲染约 5–10 秒。

## 先分流：三种情况

这个 skill 的核心是**真正的几何构造**：形状由圆、圆弧和直线算出来，构图卡上的线就是形状的来源。
Rikyū 的几何 logo 也是这样做的（反算它的猫和大猩猩，所有曲线都是精确圆弧，见 `references/method.md` §8）。

| 情况 | 判断 | 走哪条路 |
|---|---|---|
| **新做一个图标，题材简单** | 抽象图形、1–3 个字母、物件，以及 10 个以内部件能概括的动物 | 构造模式（下面的工作流） |
| **规整一个现有图标** | 用户给了图标图片，想让它更整齐、更标准 | 规整工作流（见下节） |
| **题材太复杂** | 龙、麒麟、凤凰这类鬃毛、鳞片、卷云繁多的题材 | 先建议简化成几何剪影；用户坚持要复杂版，就走外部矢量接口 `scripts/external.py`。本 skill 不内置任何第三方服务，接口是预留的（见 `references/external-vector.md`），没配置时如实告诉用户。外部生成的 SVG 用 `geoicon.py --svg` 做同样的海报、小尺寸测试和体检，但没有构图卡 |

## 规整现有图标

适合"我的 App 图标/logo 看着有点歪，帮我弄规整"这类需求。目标是找出原图标想表达的比例系统，
用精确的几何重新构造出来，而不是重新设计。

1. **测量：** `python3 <本 skill 目录>/scripts/measure.py icon.png`
   它会把图标放进 100×100 的画板，列出每个部件和镂空的 bbox、宽高、中心、形状判断（圆、矩形、胶囊、圆角矩形），
   并对并排的部件给出间距、宽度、高度比和中心对齐的偏差。浅色图形配深色背景时加 `--invert`。
2. **读出意图：** 找出接近整数比、黄金比或等距的关系。例如高度 19.9 / 42.1 / 64.4 实际是 1:2:3；
   间距 12.9 正好是 w + w/φ。偏差就是要修正的地方。
3. **写 spec：** 所有尺寸从一个模数推出（如条宽 w，或一个主半径 R），对称部分用 `mirror`，居中到画板中心。
   - App 图标的圆角用 iOS 比例 22.37%。
   - 带底色方块的图标：方块写成 `backdrop`，主体才是 `ink`，构图卡只讲主体的构造。
   - 多色：用 `paint` 给部件上色。
   - 曲边三角这类形状（帆、盾、叶）用 `arcgon`：每条边一段圆弧，半径成族（如 R、1.5R、R/φ）。
     相邻部件之间的缝，把两条边钉在同心圆上（R 和 R − g），缝宽就处处相等（见 `examples/sails.json`）。
   - 规整会改变一些"手绘的随意"。比如原图两帆之间的缝上宽下窄，规整成等宽后，后帆尖端会挪位。
     这类可见的变化要在交付时说清楚，并给出保留原貌的替代做法（例如只取同曲率、不取同心）。
4. **渲染并对比：**
   ```bash
   python3 <本 skill 目录>/scripts/geoicon.py spec.json -o out/ --compare icon.png --icon-pad 0 --icon-png 1024
   ```
   `compare.png` 并排显示"原图 | 规整后 | 叠加"，叠加图用红线画新轮廓压在半透明原图上。
   有 `backdrop` 时，原图会按"整张图 = 方块"来对齐，所以先把截图裁到方块边缘。
   `--icon-pad 0 --icon-png 1024` 输出满版 1024px 图标。
5. **复测：** 对新生成的 `poster.png` 再跑一次 `measure.py`，确认宽度、间距、中心的偏差都归零。
6. **交付四样东西，缺一不可：**
   - `construction.png`：**构图卡，规整的核心证据**。它说明新图标由哪些圆和线构成（角圆、端圆、对称轴、比例基准线），
     用户要的"通过几何图规整"就是这张。在 spec 的 `guides` 里补上讲解比例的基准线（如 1:2:3 三档高度的上下沿）。
   - `compare.png`：原图、规整后、叠加三联对比。
   - `icon.png` / `icon.svg`：成品。
   - 一张数值前后对比表：哪些尺寸从多少改成多少，比例系统是什么。

   同时提醒：iOS 提交 App Store 要用满版无圆角的方图（`"r": 0`），系统会自己加遮罩；
   原图的渐变、描边、光泽这类质感不在本 skill 范围内，规整后是纯扁平图形。

## 工作流（构造模式）

1. **定概念。** 写一句话 concept（会印在卡片上），并选原型：物件图形、动物剪影或圆形徽章/家纹。
   用户的品牌名放 `title`。没有就用物件名。
2. **拆部件，给每个部件找几何原型。** 先在脑子里（或注释里）列清单，例如"头=圆，身体=两圆的 hull，尾巴=渐细的相切弧链"。
   速查见下表，更多配方见 `references/method.md` §5。
3. **定比例系统。** 在 `vars` 里只放 2–4 个基准量：一个主半径、一个 gap、必要时一个模数。其余尺寸都由它们推导
   （`R/phi`、`2*U`）。半径控制在 5 种左右，gap 全图只用一个值。关键点要么落在 0.5 网格上，要么由几何推出
   （`polar`、`on`、`meet`、切点）。
4. **写 spec。** 画板 100×100，y 轴向下；角度 0°=右、90°=下、−90°=上；正的 turn 是屏幕上顺时针。
   完整语法见 `references/spec.md`，写之前先读它。`examples/` 里的样例都能直接跑通，可以照着改。
5. **渲染。**
6. **看图自检，迭代 2–4 轮。** 用 Read 打开 `construction.png` 和 `sizes.png`，读 `report.txt`，对照下面的清单改 spec 再渲染。
   第一版几乎总要调整：部件位置、比例、gap 是否切掉了小碎片、构造线是否太乱。
7. **交付。** 给出 `poster.png`、`construction.png` 和 `icon.svg` 的路径，再用两三句话讲构造逻辑：
   用了哪几个圆、什么比例、哪里用 gap 分层。

## 原型速查

| 想表达 | 用 | 备注 |
|---|---|---|
| 头、身体、轮子、眼睛 | `circle` | 最常用；同一半径多次复用 |
| 镜头、靶心、眼眶、外环 | `ring` | 同心环，环宽用模数 |
| 圆角机身、按钮 | `rect` + `r` | 角圆会自动画成构造圆 |
| 叶、花瓣、火焰、机身尖头、眼睛杏仁形 | `lune`，`bulge: [b, -b]` | 两条等弧夹成的 vesica |
| 鳍、翅、月牙、鬃毛片 | `lune`，`bulge: [b1, b2]` 同号 | 两弧同侧，形成新月 |
| 四肢、颈、梁 | 两圆的 `hull`，或定宽 `stroke` | hull 的直边就是外公切线，会延长成构造线 |
| 尾巴、触手、藤蔓、飘带 | `turtle` + 渐细 `w: [粗, 细]` | 由相切圆弧串成，保持 G1 连续 |
| 卷曲、漩涡 | `turtle` 的 `spiral` 步 | 每 90° 半径 × 1/φ，即黄金螺旋 |
| 花、齿轮、太阳、家纹中的重复单元 | `repeat` | 绕中心旋转阵列 |
| 左右对称 | `mirror` | 自动画对称轴虚线 |
| 前景部件压在后景上 | ink 中 `{"add": X, "gap": g}` | 先挖出 X 外扩 g 的槽，再填 X。动物剪影靠这个分出手臂、腿、尾巴 |
| 地面线、平底 | `{"cut": 地面以下的大 rect}` | 着地点落在同一条水平线上 |
| 让一条直边微微外鼓（背线、前臂） | 在那条切线上叠一个单值 `lune` | 弦就是原来的直边，拱高 1.5–3 |
| 凹角补顺 | 修饰符 `"blend": r` | 只把凹角补成半径 r 的圆弧，凸弧不变；r 取 1–5 |
| 整条有机轮廓 | `chain` | 像皮带绕过一串圆：正半径外凸、负半径内凹、0 是尖角 |

## 复杂动物剪影

动物最容易做成"熊"或"机器人"。下面这些是迭代大猩猩时踩出来的规律，做四足或灵长类之前先读
`references/method.md` §7。
- **肢体用两个关节圆的 hull**，得到干净的锥形，大小顺序是"肌肉 → 收束 → 手脚"。
  把一串圆直接相交会变成串珠（气球动物），blend 也救不回来。
- **大轮廓要有弧度**：背线、前臂前缘这些长直边，各叠一个浅 lune 鼓出去。
  小圆加长切线只会得到圆角多边形，看起来像机器人。
- **物种靠特征识别**，不靠细节数量：大猩猩是颅顶、眉骨、吻部、前臂毛簇，以及肩高于臀；
  熊没有颅顶，前臂也不粗。先列出 3–4 个特征，逐个给它们找几何构造。
- **远侧肢体**放在前景肢体之间留出的空隙里，不要和毛簇、手脚重叠，否则 gap 会把它切成碎条。
- **一次只改一两处**，每轮都看 poster 和 sizes。保留每一版 spec，退步了可以回滚。

## 最小样例

```jsonc
{
  "name": "camera", "title": "Camera",
  "concept": "A camera drawn from concentric circles and level, straight edges.",
  "vars": {"U": 3.5, "R0": 20},
  "points": {"C": [50, 55]},
  "shapes": {
    "body":  {"rect": {"c": "C", "w": 72, "h": 46, "r": 13}},
    "hole":  {"circle": ["C", "R0"]},
    "ring":  {"ring": {"c": "C", "r_out": "R0 - U", "r_in": "R0 - 2.3*U"}},
    "glass": {"circle": ["C", "R0 - 3.3*U"]}
  },
  "ink": ["body", {"cut": "hole"}, "ring", "glass"],   // 按顺序：加、挖、再加
  "guides": [{"axis": true}, {"hline": "C.y"}]          // 额外的纯构造线
}
```

## 自检清单

看 `sizes.png`：
- 32px 还能认出来吗？16px 至少剩个轮廓？认不出就删细节、加粗、放大缝。

看 `construction.png`：
- 每段轮廓都能指认出来自哪个圆或哪条线吗？指认不出就说明在"画"而不是在"构造"。
- 构造线是否乱得失去说服力？对纯辅助部件用 `"guide": false` 或 `"circles"` 降噪。保留能讲清比例关系的圆。
- 重心是否稳？站立的物体要有地面线，物件类通常严格对称。

看 `report.txt`：
- `tiny island`：gap 或 cut 切出了孤立小碎片，调整部件位置或 gap。
- `thin parts`：细于 `min_feature`（默认画板 2%）的部位，小尺寸会断。
- `tight gaps`：窄于 `min_gap`（默认 1.2%）的缝，小尺寸会糊。
- `radii` 超过 6 种：合并相近半径，改用比例推导。

整体：
- 单色、无渐变、无描边、无文字。负空间是设计的一部分。
- 原创。不要模仿现有品牌的 logo，也不要套用受版权保护的角色形象。

## 常见坑

- **lune 的 bulge 正负**：正值鼓向"从 a 走到 b 时的右手边"（屏幕上看）。从上往下走 (↓) 时正值鼓向左，
  从左往右走 (→) 时正值鼓向下。叶形用 `[b, -b]`，不用管方向。
- **gap 的顺序**：gap 只作用于它之前已经画上的墨迹（画家算法）。需要压在上面的部件放后面。
- **`round` 会吃掉细部**：圆角半径大于部件半宽时，部件会被整个抹掉。
- **mirror 默认保留原件**（`keep: true`），镜像轴默认是 x=50。部件只画左半边，镜像到右边。
- **构造线太多**：poly 的每条边都会延长成全幅直线。三角耳朵这类部件可以保留线，纯辅助部件设 `"guide": false`。
- **文字**：图标里不要放字。需要字标时在交付说明里另行建议。
- **chain 的凸圆必须伸出相邻两圆的切线之外**：否则皮带会绕它一整圈，鼓成一个球。
  脚本会自动跳过这种圆，并在 `report.txt` 里写一条 `warning`，看到时把圆往外挪或放大。
- **`blend` 不是万能的**：它只补凹角。圆和圆之间距离太远时，blend 太小会留下串珠状凹口，
  太大又会抹平特征。
- **radii 警告**：有机动物通常会用到 10–20 种半径，这正常。主体积（躯干、头、大腿、上臂）的半径保持成族就够了。
- **想要"可验证"的输出就少用 blend / soften / round**：它们产生的过渡弧不是构造圆，`icon.svg` 里只能写成折线，
  构图卡上也看不到。`report.txt` 第一行会给出轮廓里精确圆弧、直线、折线各占多少；几何 logo 的目标是折线接近 0%。
  需要倒角时，用一个显式的小圆（加进 union 或 chain）代替。
- **构图卡太乱或太空**：默认只画最终落在轮廓上的圆和线。想看全部构造（调试用），在 spec 里写 `"show": "all"`，
  或在命令行加 `--all-guides`。
